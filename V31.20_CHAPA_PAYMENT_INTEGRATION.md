# BMT V31.20 – Chapa Payment Integration

## What changed
- Added server-side Chapa checkout initialization.
- Plan amount/currency are controlled by the BMT server.
- Added Chapa callback verification.
- Added Chapa webhook verification with HMAC signature.
- Webhook/callback always re-query Chapa before granting premium access.
- Amount and currency are checked against the BMT payment record.
- Existing transaction approval remains atomic and idempotent.
- Student payment UI now makes Chapa the primary checkout and keeps manual payment as a fallback.
- No Chapa secret is exposed to browser JavaScript.

## Render environment variables
- `CHAPA_SECRET_KEY` = Chapa secret key (server only)
- `CHAPA_WEBHOOK_SECRET` = random webhook secret configured in Chapa Dashboard
- `BMT_BASE_URL` = public BMT URL, e.g. `https://your-service.onrender.com`
- `PAYMENT_CURRENCY` = `ETB`

Keep all four server-side. Never put `CHAPA_SECRET_KEY` in HTML or JavaScript.

## Chapa Dashboard
Configure webhook URL:
`https://YOUR-BMT-DOMAIN/api/payments/webhook/chapa`

Use the same webhook secret in `CHAPA_WEBHOOK_SECRET`.

## Flow
Student → BMT server → Chapa checkout → payment → Chapa callback/webhook → BMT re-verifies transaction → amount/currency match → atomic entitlement unlock.

## Important
This release does not claim a live payment PASS until a real Chapa test transaction has been completed on the deployed Render service.
