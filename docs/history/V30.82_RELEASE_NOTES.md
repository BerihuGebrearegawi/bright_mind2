# BMT V30.83 — Production Storage Architecture

## Architecture
- Render: Flask application/API server.
- Firestore: application database, progress, chat and metadata.
- Cloudinary: images, videos and audio.
- Google Cloud Storage: books, PDFs, DOC/DOCX and original teacher AI-material files.

## Storage hardening
- Added authenticated server-side GCS document upload.
- Added short-lived V4 signed URLs for document access.
- Removed Cloudinary as the default document/PDF provider for new uploads.
- Added GCS object-path metadata so documents are not tied to expiring URLs.
- Student book UI refreshes GCS URLs when opening/downloading.
- Exam archive accepts GCS as the recommended provider while preserving legacy providers.
- Teacher AI-material PDFs are stored in GCS while extracted/searchable text remains in Firestore.
- Added non-secret GCS configuration status to the admin diagnostics endpoint.

## Required Render variable
- `GCS_BUCKET_NAME`

The existing Firebase service-account environment variable is reused server-side. No service-account secret is shipped to the browser or release ZIP.
