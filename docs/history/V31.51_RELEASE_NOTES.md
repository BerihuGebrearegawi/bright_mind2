# BMT V31.51 — Verification-First Hardening

## Repairs
- Challenge attempts capture an immutable server-side question snapshot at start, including the grading key and point values; clients never receive the grading key.
- Resume and grading use the immutable attempt snapshot for new attempts, preventing later question edits from changing an active competition.
- Free challenge registration no longer requires a payment record.
- Paid challenge entries require an already verified payment explicitly scoped to the same challenge.
- Firestore rules for the new Library/Challenge collections are correctly nested inside the documents service and remain browser-denied where server authority is required.
- Challenge scheduling rejects timezone-naive timestamps.
- Certificate issuance is transaction-protected against concurrent duplicate issuance.
- Award finalization refuses to run while a scheduled challenge is still open.
- Corrected the legacy static regression assertion to match the verified V31.30 service-worker baseline (`bmt-shell-v31-29`).

## Boundary
- No ChatGPT A-owned UI/auth/payment implementation was rewritten.
- Existing payment endpoints are unchanged; challenge-entry verification safely requires challenge-scoped payment metadata for paid challenges.
