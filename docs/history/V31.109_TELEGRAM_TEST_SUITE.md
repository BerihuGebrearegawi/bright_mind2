# V31.109 — Real Automated Tests for the Telegram Bot Subsystem

## Problem
The existing `scripts/*_regression_test.py` files are static string-matching
checks (e.g. "does this exact substring appear in this file"). They catch
accidental deletion of a line, but they never actually run the Flask routes,
so they cannot catch a real behavioural regression (wrong status code, wrong
role check, wrong Telegram API payload, wrong escalation threshold, etc.).

## What was added
A real `pytest` suite under `tests/` that boots each Telegram route module as
an actual Flask app, sends it real HTTP requests via Flask's test client, and
asserts on real behaviour:

- `tests/fakes.py` — an in-memory Firestore fake (`FakeFirestore`) supporting
  `collection/document/where/limit/stream/get/set/update`, and a
  `FakeTelegramAPI` that replaces `requests.post` so no real network call is
  ever made and every call BMT makes to the Telegram Bot API can be inspected
  and asserted on.
- `tests/conftest.py` — stubs `firebase_admin` in `sys.modules` (the real
  package is not required to run tests) and provides `fake_db`,
  `firebase_configured`, `firebase_not_configured`, and `telegram_api`
  fixtures.
- `tests/test_telegram_moderator_bot.py` (12 tests) — webhook secret auth,
  the `/start` menu, spam detection (suspicious phrases, excessive links,
  excessive mentions), and the delete → mute (≥2 prior violations) → ban
  (≥5 prior violations) escalation path.
- `tests/test_telegram_publisher_bot.py` (12 tests) — webhook secret auth,
  the admin/approved-teacher staff gate, the canonical 12-target listing,
  the select-target → forward-content publish flow, and the web-dashboard
  `send-quiz` endpoint (approved vs. not-approved questions).
- `tests/test_telegram_platform_routes.py` (15 tests) — role gating
  (student/unapproved-teacher/approved-teacher/admin), the Smart List Builder
  grade/purpose filtering, multi-target publish + `telegramPosts` logging,
  target-count and content-type validation, and the scheduler-tick secret +
  due/future schedule handling.
- `tests/test_telegram_challenge_routes.py` (10 tests) — webhook secret auth,
  server-side Telegram→student identity mapping (a teacher/admin's
  `telegramUserId` must never be accepted here), and the `/challenges`
  published/grade/region/date filtering.

**49/49 tests pass.**

## Running the tests
```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

## Scope / what this does not cover yet
This suite covers the Telegram bot subsystem only (the module most recently
audited in depth). The same fake-Firestore + Flask-test-client pattern can be
extended to `parent_routes.py`, `teacher_routes.py`, `student_profile_routes.py`,
and the other `*_routes.py` files — that is a natural next phase, not done here.
It does not replace the existing `scripts/*_regression_test.py` static checks,
which still catch a different class of mistake (accidental deletion of a
security-relevant line) cheaply; both can coexist.
