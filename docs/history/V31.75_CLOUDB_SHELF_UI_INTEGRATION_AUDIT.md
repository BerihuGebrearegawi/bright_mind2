## V31.75 A deployment-preflight hardening
- Added `GEMINI_API_KEY` to `render.yaml` as a secret (`sync: false`) because the application and Scanner require it.
- Added `GEMINI_MODEL` and `GEMINI_VISION_MODEL` as deployment-configurable secrets/values (`sync: false`) so model selection is explicit and does not require source edits.
- Added `TELEGRAM_BOT_TOKEN` and `TELEGRAM_WEBHOOK_SECRET` as deployment secrets (`sync: false`).
- Added `TELEGRAM_MAX_MESSAGE_LENGTH` with the code's documented default of 3500.
- Retained the established service-worker shell cache key `bmt-shell-v31-29`; the worker install path refreshes the shell cache contents when the worker updates, and the static regression suite explicitly guards this established baseline.

These are deployment-preflight configuration changes only. No Telegram target IDs, credentials, Firestore schema, or ownership boundaries were invented or changed.
