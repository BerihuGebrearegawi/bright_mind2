# BMT V31.57 — Award Finalization Consistency Hardening

## Scope
Additive hardening for the BMT Academic Challenge award pipeline. No A-owned UI/auth/payment implementation was intentionally changed.

## Changes
- Made award finalization idempotency atomic by re-checking the challenge's finalized state inside a Firestore transaction before writing the award ledger.
- Prevented concurrent admin finalization requests from independently publishing conflicting award ledgers.
- Preserved deterministic winner ordering and server-derived eligibility.
- Made award preview prize allocation use the same cent-remainder rule as the finalized award ledger, so preview and final ledger cannot disagree by rounding remainder.
- Preserved verified-entry-only revenue for paid challenges.
