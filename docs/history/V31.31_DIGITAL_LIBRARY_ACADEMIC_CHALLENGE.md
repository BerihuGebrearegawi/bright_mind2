# BMT V31.31 — Digital Library + Academic Challenge Foundation

## Scope
Additive backend foundation for the next BMT learning layer. Existing authentication,
payments, legacy quizzes, and advanced exam contracts are preserved.

## Digital Library
- Existing `/api/library` remains unchanged.
- Adds server-authoritative book structure lookup at `/api/library/structure/<book_id>`.
- Adds approved teacher/admin chapter creation at `/api/teacher/library/chapters`.
- Library structure is optional and does not alter existing book records.

## Question Bank
- New server-only `questionBank` collection.
- Questions begin as `draft` and require explicit approval before challenge use.
- Correct answers are never returned by the question-bank read API.

## Academic Challenge
- New server-only `academicChallenges` and `challengeAttempts` collections.
- Only approved questions can be placed into a challenge.
- Challenge start creates a server-side deadline.
- Submission score is calculated from the server-side question bank; client score/rank/prize fields are ignored.
- Student leaderboard responses do not expose other students' user IDs.

## Security
- New Firestore collections inherit the existing deny-by-default fallback because all authoritative reads/writes use the Firebase Admin SDK through Flask.
- Existing auth/role checks are reused.
- Existing global API rate limiting and security headers remain active.
- No new paid AI provider call is introduced by V31.31.

## Cost control
The new foundation is deterministic and does not call Gemini. AI/OCR can be attached later behind an explicit provider boundary and quota/cache layer.

## Parallel tracks
- Track A: Digital Library → chapter structure → reader integration.
- Track B: Question Bank → timed challenge → scoring/ranking.
- Shared gate: authentication → authorization → validation → audit/testing → integration.
