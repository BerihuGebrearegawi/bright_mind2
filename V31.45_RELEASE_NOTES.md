# BMT V31.45 — Challenge Entry Payment Verification Bridge

## Scope
Additive server-side bridge between an already-approved BMT payment and the Academic Challenge `challengeEntries` collection.

## Safety boundaries
- Existing payment routes are not modified.
- A client cannot supply the challenge fee or override the verified payment amount.
- Payment must already be server-approved and belong to the authenticated student.
- The stored payment plan must be a challenge-entry plan.
- Amount and currency must exactly match the challenge's server-stored entry fee.
- Entry creation is idempotent per challenge + student.
- Challenge entry records remain server-only through Firestore rules.
- Admin entry-fee configuration is server-authorized.

## Integration path
Existing payment verification -> `/api/challenges/<id>/entry/confirm` -> verified `challengeEntries` -> award finalization -> certificate.

## Validation
Python compile check and static route-contract checks performed for the V31.45 additions.
