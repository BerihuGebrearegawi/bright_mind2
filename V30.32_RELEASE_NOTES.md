# Bright Mind Tutor V30.32

## Focus
Production hardening, API safety, observability, and failure handling.

## Changes
- Added request IDs for API observability and support diagnostics.
- Added security response headers (`nosniff`, `DENY`, strict referrer policy, permissions policy).
- Added `Cache-Control: no-store` to API responses to reduce accidental sensitive-response caching.
- Added a configurable global request-size limit via `MAX_CONTENT_LENGTH` (2 MiB default).
- Added a safe JSON response for oversized requests.
- Hardened the FCM admin sender with a maximum of 500 tokens and input validation.
- Health endpoint now reports platform version 30.32 and request ID.
- Preserved V30.31 teacher approval, payment authorization, and Firebase admin-claim security.

## Compatibility
No public route was removed. Existing data structures are preserved.

## Validation
- Python compilation: passed for core Flask and route modules.
- JavaScript syntax checks: passed for admin.js, student.js, and teacher.js.
- Health endpoint test: passed.
- ZIP integrity: passed after packaging.

## Known limitations
- Production HTTPS/HSTS remains the responsibility of the deployment platform. HSTS is intentionally not forced in local HTTP development.
- `ALLOWED_ORIGINS` should be explicitly configured in production. If omitted, API CORS remains permissive for backward compatibility.
