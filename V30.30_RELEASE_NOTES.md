# V30.30 Release Notes

Baseline: V30.29

Focus: Parent portal + verified parent-child analytics + cross-role security foundation.

## Added
- `/parent` portal route.
- Server-authoritative parent-child relationship verification.
- `GET /api/parent/children`.
- `GET /api/parent/children/<child_id>/progress`.
- `GET /api/parent/children/<child_id>/analytics`.
- `GET /api/parent/children/<child_id>/assessments`.
- Responsive parent dashboard with child selection, learning metrics, topic mastery and assessments.
- Firestore rules explicitly block direct browser access to `parentChildLinks` and `studentAnalytics`.

## Security
- Parent endpoints require Firebase ID-token authentication.
- Child access requires a verified `parentChildLinks` record with `status == verified`.
- Arbitrary child IDs cannot bypass the relationship check.
- Parent portal exposes read-only analytics and assessment information.
- No parent endpoint writes grades, attendance, enrollment, teacher records or payment state.

## Data model
Uses the V30.21 model:
- `parentChildLinks/{linkId}`
- `studentAnalytics/{studentId}`

## Important limitation
Final production verification requires Firebase service-account credentials and representative verified parent-child data in the runtime environment.

## QA
- Python syntax compile check.
- Parent route registration check.
- Firestore rules syntax should be validated with the Firebase Emulator before deployment.
