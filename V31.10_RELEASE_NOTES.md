# BMT V31.10 — End-to-End Registration and Parent Linking Hardening

## Critical fixes
- Student, teacher and parent self-registration profiles now include a non-privileged `accountType` marker.
- Teacher and parent registrations now satisfy the Firestore self-registration contract (`freeTrial.isActive=true`).
- Teacher media reply flow no longer sends the same media message twice.
- Parent APIs verify the authenticated account is a parent before exposing parent data.
- Added secure Admin-only `/api/admin/parent-links` to link a parent account to a student account.
- Added Admin UI for parent/student linking.
- Parent dashboard can now consume verified links through server-authoritative APIs.
- Service-worker cache bumped to `bmt-shell-v31-10`.

## Validation
- Python syntax: PASS
- JavaScript syntax (`node --check`): PASS for student, teacher, admin and recovery scripts
- Existing static regression suite updated to V31.10 and executed
- Security rule and public smoke tests are included for deployment validation

## Important deployment test
A successful build is not proof of Firebase production health. After deployment, test each real flow:
1. Student register → login → dashboard → logout
2. Teacher register → application → admin approval → teacher dashboard → logout
3. Parent register → admin parent/student link → parent dashboard → child analytics/results → logout
4. Forgot password on all portals
5. Exam start → answer → submit → result → parent result visibility
