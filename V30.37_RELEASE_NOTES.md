# Bright Mind Tutor V30.37 Release Notes

## Focus
Role-based client authorization hardening and removal of hard-coded administrator identity from frontend code.

## Changes
- Removed hard-coded administrator email checks from `static/admin.js` and `static/student.js`.
- Admin dashboard now checks Firebase custom claims (`admin === true` or `role === "admin"`) before rendering privileged UI.
- Student dashboard detects admin accounts from Firebase custom claims and redirects them to the Admin Panel.
- Forced token refresh is used during role verification so stale claims are less likely to grant incorrect UI access.
- Registration/login no longer relies on a hard-coded administrator email block.
- Backend `/_require_admin_bearer()` and Firestore security rules remain the authoritative security boundaries.
- Preserved V30.36 rate limiting, request IDs, proxy-header hardening, CORS controls, HSTS, Firebase revocation checks, payment security, and AI security.

## Security Rationale
Frontend email allowlists are not an authorization boundary. V30.37 removes that fragile dependency and aligns the UI with the server-side custom-claim model already used by the backend.

## Deployment Requirement
Before production deployment, ensure authorized administrators have Firebase custom claims such as:
- `admin: true`
- or `role: "admin"`

Never place service-account credentials or provider secrets in frontend code.
