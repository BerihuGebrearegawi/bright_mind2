# BMT V31.01 — Examination Data Model & Results Hardening

## Exam document: `exams/{examId}`
- title
- className
- durationMinutes
- passMark (0–100)
- maxAttempts (1–20)
- totalPoints
- questions[]: question, type, topic, options, points
- teacherUid
- status
- createdAt / updatedAt

## Answer key: `examKeys/{examId}`
- examId
- teacherUid
- answers: {questionIndex: correctOption}
- points: {questionIndex: points}
- topics: {questionIndex: topic}
- passMark

Answer keys are not returned by student exam-list APIs.

## Attempt: `examAttempts/{attemptId}`
- examId / examTitle
- userId
- className
- status: started | submitted
- answers
- startedAt / deadlineAt / updatedAt
- submittedAt
- score / totalPoints / percentage
- passMark
- topicStats
- weakTopics

## Result contract
A completed attempt exposes PASS/FAIL using the server-stored pass mark and a detailed review to the owning student only. Correct answers are never accepted from the browser for grading.

## V31.01 hardening
- Maximum attempts enforced server-side.
- Teacher/admin accounts are prevented from starting student exam attempts when their Firebase custom role is present.
- Result endpoint refuses incomplete attempts.
- Detailed result includes question-level review only after submission.
