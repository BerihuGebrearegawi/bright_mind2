# Bright Mind Tutor V30.31

## Focus
Security and quality hardening of privileged administration workflows.

## Changes
- Teacher approval and rejection moved from direct browser Firestore writes to server-authoritative Flask endpoints.
- Approval/rejection now validates the request state and target user on the backend.
- Teacher approval records approver and timestamp.
- Teacher rejection records reviewer, timestamp, and optional reason.
- Existing payment approval remains server-authoritative.
- Admin authorization now supports Firebase custom claims (`admin: true` or `role: admin`) while preserving the existing legacy admin email fallback for compatibility.
- Firestore `isAdmin()` now recognizes the same additive claim-based admin model.

## Security impact
A compromised or modified admin browser can no longer directly perform the teacher approval workflow by writing the `teacherRequests` and `teachers` collections. The backend now becomes the authoritative workflow.

## Compatibility
No existing public route was removed. Existing V30.30 data structures remain compatible.

## Validation
- Python compilation: passed.
- ZIP integrity: passed before V30.31 changes.
- JavaScript syntax should be checked in CI/build environment with the project's browser module setup.

## Known limitations
- The legacy admin email fallback remains for backward compatibility. Production deployments should migrate to Firebase custom claims and then remove the email fallback.
- Telebirr/CBE webhook adapters still require real provider-specific credentials/signature configuration before production automated verification.
