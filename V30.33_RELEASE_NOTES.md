# Bright Mind Tutor V30.33

## Focus
Authorization cleanup and production configuration hardening.

## Changes
- Removed the hard-coded administrator email fallback from Flask authorization.
- Removed the hard-coded administrator email fallback from Firestore `isAdmin()` rules.
- Admin access is now based only on trusted Firebase custom claims (`admin == true` or `role == 'admin'`).
- CORS no longer silently becomes permissive when `ALLOWED_ORIGINS` is missing.
- Added an explicit `ALLOW_PERMISSIVE_CORS=1` escape hatch for controlled development/testing only.
- Health endpoint reports version 30.33.
- Preserved V30.32 request IDs, security headers, request-size protection, API no-store behavior, and FCM validation.

## Security Rationale
A production admin identity must not depend on a source-code email address. Administrator authorization is now claim-based and centrally controlled through Firebase authentication/custom claims.

## Deployment
Recommended production configuration:
- Set `ALLOWED_ORIGINS` to the exact production frontend origins.
- Leave `ALLOW_PERMISSIVE_CORS` unset or `0` in production.
- Grant admin access only through trusted Firebase custom claims.
