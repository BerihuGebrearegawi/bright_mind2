# V30.31 Security Audit

## Finding fixed: client-side teacher approval
**Before:** admin.js directly updated `teacherRequests` and created/updated `teachers` documents.

**Risk:** authorization logic was split between the browser and Firestore rules. A privileged workflow should not depend on browser behavior.

**After:** approval/rejection are authenticated server endpoints protected by the existing admin bearer check.

## Finding fixed: admin identity model
**Before:** backend and Firestore rules depended primarily on one hard-coded admin email.

**After:** additive support for Firebase custom claims:
- `admin == true`
- `role == "admin"`

The existing email remains as a compatibility fallback.

## Remaining production actions
1. Configure Firebase custom claims for real administrators.
2. Remove the legacy email fallback after claims are confirmed.
3. Configure actual provider-specific Telebirr/CBE webhook signature verification.
4. Add automated integration tests against a Firebase emulator before production deployment.
